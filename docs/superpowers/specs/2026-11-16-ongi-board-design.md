## 1. 기획 의도 및 배경 (Intent & Why)

많은 사람들이 공부·운동·독서·드로잉 등 자기계발을 꾸준히 하고 싶어 하지만, 다음과 같은 이유로 쉽게 흐름이 끊긴다.
- **결과 지연의 문제**: 하루 이틀 쉰다고 당장 문제가 생기지 않고, 하루 이틀 했다고 해서 눈에 띄는 성과가 바로 드러나지 않는다.
- **기존 앱의 한계**: 개인 투두/체크리스트는 죄책감만 남기고, 오픈채팅방 기반 인증은 잡담·인사치레 피로와 ‘유령방(절반 이상 잠수)’ 문제로 빠르게 식는다.

**온기보드**는 **자기계발 전용 셋로그(Setlog) 스타일 사진 인증 앱**이다. 같은 분야에 관심 있는 소규모 인원(2~6명)이 하나의 분할 사진 보드를 공유하며, 텍스트 수다 없이 **‘인앱 실시간 촬영 사진 한 장 + 짧은 한마디’**만으로 서로에게 시각적 자극과 따뜻한 연결감을 준다. 다른 멤버들이 보드를 채워갈수록 비어 있는 내 칸이 자연스럽게 행동을 유도하고, 사진 한 장을 찍는 즉시 그룹 합동 포스터 완성 및 내 개인 앨범 누적이 일어나 즉각적인 성취감을 제공한다.

## 2. 목표 / 비목표 / 안티골 (Goals, Non-Goals, Anti-Goals)

### 목표 (Goals)
1. **무제한 자유 주제 지원**: 운동·독서·코딩·그림·자격증·기상 루틴 등 세상의 모든 자기계발을 자유 `#태그` 기반 방으로 수용한다.
2. **인원수에 맞춘 가변형 분할 보드**: 방 정원(2/4/6명)이 다 차기 전(1~3명)에도 빈 구멍 없이 현재 인원수(`1칸 / 2분할 / 3분할 / 2×2 / 2×3`)에 맞춰 보드가 자동 구성되어 즉시 시작할 수 있다.
3. **인앱 실시간 촬영 전용 인증**: 허위/재탕 인증을 막기 위해 갤러리 업로드를 제한하고, 앱 내 카메라로 지금 찍은 사진에 타임스탬프와 방 태그를 입혀 즉시 올린다.
4. **지속 가능한 그룹 유지 장치**: 피치 못할 날을 위한 **주 1회 휴식권 스티커**와 **3일 연속 미인증 잠수 멤버 자동 정리**로 유령방 고립을 방지한다.
5. **명확한 3대 화면 + 아카이브 구조**:
   - **내 참여 방 목록(홈)** → **단일 방 몰입 풀스크린 폴라로이드 보드(+ 그룹 달성률)** → **미달 방 우선 탐색 및 새 방 개설** + **내 앨범(월간 달력)**.

### 비목표 (Non-Goals)
- **필수 할 일(일반 투두 리스트) 관리 제외**: 업무·생활 할 일은 다루지 않으며 오직 자기계발 인증에만 집중한다.
- **분야별 전용 트래커 제외**: 독서 페이지 계산기, 운동 세트·중량 입력기, 타이머 같은 분야 종속 기능을 강제하지 않는다.

### 안티골 (Anti-Goals)
- **단체 채팅방화 금지**: 자유 텍스트 채팅창을 두지 않으며, 짧은 한 줄 코멘트와 가벼운 리액션(하트)으로만 소통한다.
- **차가운 대시보드/AI 기본 템플릿 느낌 금지**: 딱딱한 다크 표·관리자 어투·이모지 남발 대신, 따뜻하고 친근한 아날로그 폴라로이드 다이어리 감성(`/frontend-design` Cozy Daylight)을 끝까지 유지한다.

## 3. 제약사항 및 플랫폼 전략 (Constraints & Mobile Packaging)

- **기술 스택**: Next.js (App Router, TypeScript) + 로컬 SQLite DB 풀스택 웹앱.
- **iOS/Android 스토어 확장성 (Capacitor 호환 설계)**:
  - 모든 화면은 모바일 앱 규격(최대 너비 `430px` 기준 1열 레이아웃, 데스크톱에서는 따뜻한 캔버스 중앙에 모바일 뷰포트 프레임 또는 풀스크린 반응형 전환)과 터치 타겟(`44px` 이상)을 준수한다.
  - 카메라/스토리지 어댑터를 UI 컴포넌트와 분리해 두어, 추후 `Capacitor`로 래핑 시 `@capacitor/camera` 네이티브 브릿지로 즉시 교체할 수 있도록 설계한다.
- **인앱 실시간 카메라 & PC 환경 폴백** `[설계자 기본값 결정]`:
  - 기본 경로는 `navigator.mediaDevices.getUserMedia` 실시간 웹캠 스트림 + `<canvas>` 캡처(자동 타임스탬프 & 방 태그 워터마크 합성)를 사용한다.
  - 갤러리 파일 선택(`<input type="file">`)은 제공하지 않는다.
  - 단, 카메라 하드웨어가 없거나 권한이 차단된 데스크톱 테스트 환경에서는 뷰파인더 내에 안내와 함께 **실시간 프리뷰 캔버스 스냅샷 폴백 모드**를 제공해 전체 인증 플로우를 막힘없이 검증할 수 있게 한다.
- **사용자 식별(MVP 간편 세션)** `[설계자 기본값 결정]`:
  - 별도 로그인/회원가입 화면 없이 즉시 핵심 경험을 테스트할 수 있도록 기본 사용자 프로필(`나`, `user_me`)을 로컬 DB 및 브라우저 쿠키/스토리지에 자동 연결한다(추후 OAuth/로그인 추가 용이).
- **인증 이미지 저장** `[설계자 기본값 결정]`:
  - 캡처된 사진은 압축 JPEG(`canvas.toDataURL('image/jpeg', 0.82)` 또는 `public/uploads/` 로컬 파일 기록) 형태로 저장해 로컬 환경에서 외부 스토리지 키 없이 즉시 동작하도록 한다. (Capacitor/프로덕션 전환 시 S3/R2 업로드 어댑터로 교체 가능)

## 4. 검토한 구현 방식 (Approaches)

| 방식 | 구성 | 장점 | 트레이드오프 |
| :--- | :--- | :--- | :--- |
| **방식 1** | React + Vite 클라이언트 전용 (PWA) | 초기 설정이 가장 단순함 | 브라우저 `localStorage`에만 남아 다중 기기·멀티유저 방 공유 확장이 어려움 |
| **방식 2 (선택)** | **Next.js (App Router) + 로컬 SQLite DB 풀스택 + Capacitor 패키징 호환** | 확정한 웹 CSS/타이포/종이 질감을 100% 그대로 구현하면서도 서버 API·DB 구조가 한 번에 잡히고, 이후 Capacitor로 iOS/Android 스토어 출시 가능 | Next.js 서버와 로컬 DB 파일 관리가 필요함 |
| **방식 3** | React Native + Expo 네이티브 앱 | 처음부터 네이티브 바이너리 중심 | 웹 감성 디테일(반투명 블러·복합 폰트·질감) 재현 비용이 크고, 서버·DB를 어차피 별도 구축해야 함 |

**선택 이유**: 디자인 완성도와 개발 속도를 지키면서 실제 방/인증/달성률 데이터를 영속 DB에 저장하고, 추후 `Capacitor`를 통해 iOS/Android 스토어까지 연결할 수 있는 **방식 2**를 채택한다.

### 5.2 화면별 기능 명세
1. **화면 1: 내 참여 방 목록 (`/`, 홈)**
   - 상단 인사말, 참여 방 개수, 이번 주(월~일) 내 전체 인증 흐름 도트 바 표시.
   - 참여 중인 방 카드 목록: `#태그`, `Day N` 연속 기록, 방 제목, 내 상태 배지(`오늘 나의 순간 남기기` 코랄 / `오늘 인증 완료` 세이지 / `오늘 휴식권 사용` 허니), 현재 인원에 맞춘 **미니 폴라로이드 프리뷰**, **오늘 그룹 달성률 프로그레스 바(`75%` 등)**.
   - 방 카드를 누르면 해당 방(`/rooms/[id]`)으로 이동한다. 하단 탭바(`내 방 목록`, `방 탐색`, `내 앨범`) 제공.

2. **화면 2: 특정 방 내부 (`/rooms/[id]`, 단일 방 몰입 보드)**
   - **단일 방 몰입 원칙**: 상단에 다른 방으로 바로 점프하는 탭을 두지 않으며, 왼쪽 상단 `‹ 목록으로` 버튼을 통해서만 홈으로 나간다.
   - **상단 헤더 & 온기 카드**: 방 제목, `Day N 함께하는 중`, 달력 기록 모달 버튼(`🗓️` — 과거 날짜별 합동 포스터 열람). 바로 아래 **우리 방 온기 카드**에서 `오늘 달성률 %`, `N명 중 M명 도착!`, 멤버별 아바타 버블(`✓` / `쉼` / `나`)을 표시한다.
   - **가변형 분할 폴라로이드 보드**:
     - 현재 방 참여 인원수(`1~6명`)에 맞춰 레이아웃이 자동 결정된다 (`1명`: 1칸 단독, `2명`: 상하 2분할, `3명`: 상단 1칸 + 하단 2칸, `4명`: 2×2, `5~6명`: 2×3).
     - **1명 단독 방일 때** `[설계자 기본값 결정]`: 보드 하단에 같은 `#태그`를 가진 다른 방의 오늘 실시간 인증 썸네일 스트립을 가볍게 노출해, 정원이 차기 전에도 동기부여를 받는다.
     - 타일마다 타임스탬프, 한 줄 코멘트, 클릭 가능한 하트 리액션 버튼 제공.
   - **인앱 실시간 카메라 뷰파인더 오버레이**:
     - 내 빈칸(`오늘 나의 순간 남기기`) 탭 시 화면 전체를 덮는 카메라 뷰파인더가 열리며, 실시간 시각·방 태그·`갤러리 불러오기 불가` 안내가 표시된다.
     - 한 줄 코멘트(선택)를 입력하고 셔터를 누르면 타임스탬프가 합성된 사진이 즉시 업로드되어 보드와 달성률이 실시간 갱신된다.
   - **휴식권 스티커 (`오늘은 쉬어가기`)**:
     - 방별 주 1회(월~일 기준) 사용 가능. 사용 시 내 슬롯에 따뜻한 휴식 스티커 카드가 배치되고 방과 개인의 연속 일수(`Day N`)가 깨지지 않는다.

3. **화면 3: 새로운 방 탐색 및 개설 (`/explore`)**
   - 상단 키워드/태그 검색 입력창 + 필터 칩(`전체`, `한 자리 남았어요`, `#운동·산책`, `#독서·글쓰기`, `#드로잉·취미`, `#공부·작업`).
   - **정원 미달 방 우선 추천**: 빈자리가 있는 활성 방(특히 1자리 남은 마감 임박 방 → 진행 중인 1~2인 방 순)을 상단에 배치해 1인 방 난립을 방지한다.
   - `함께하기` 버튼 클릭 시 즉시 해당 방에 합류하고(`/rooms/[id]` 이동 가능), 하단 `+ 새로운 다정한 방 만들기` 버튼으로 바텀 시트를 열어 방 이름·자유 `#태그`·정원(`2/4/6명`)을 정해 새 방을 생성할 수 있다.

4. **화면 4: 내 앨범 (`/album`)** `[설계자 기본값 결정]`
   - 내가 모든 방에서 촬영해 올린 인증 사진과 휴식 스티커를 월간 캘린더 그리드 및 방별 필터로 모아보는 개인 아카이브 화면. 날짜를 누르면 그날 찍은 폴라로이드와 한 줄 코멘트를 크게 본다.

### 5.3 핵심 도메인 규칙 `[설계자 기본값 결정]`
- **그룹 달성률 계산**: `(오늘 사진 인증 완료 인원 + 오늘 휴식권 사용 인원) / 현재 방 참여 인원 × 100`.
- **하루 1회 인증 제한**: 한 사용자는 같은 방에 하루 1회(사진 또는 휴식권)만 기록할 수 있다.
- **연속 달성일(`Day N`, `streak_days`) 스키마 및 갱신 규칙** `[설계자 기본값 결정]`:
  - `rooms.streak_days`는 방 전체가 함께 이어가는 연속 달성일(`Day N`)을 의미하며, `rooms.last_completed_date` (`YYYY-MM-DD`)로 당일 중복 증가를 방지한다. `room_members.member_streak_days`는 각 멤버의 개인 연속 일수를 함께 기록한다.
  - 오늘(`D`) 현재 방 멤버 **100% 전원이 슬롯을 채웠을 때**(`status = 'photo'` 또는 `'rest'` 모두 활성 일수로 인정), `rooms.last_completed_date !== D`인 경우에만 갱신한다:
    - 직전 완료일이 어제(`D-1`)이거나 방금 시작한 경우(`last_completed_date === D-1` 또는 초기 시드 연속 상태): `streak_days += 1` 후 `last_completed_date = D`.
    - 전날(`D-1`)을 통째로 놓쳐 공백이 생긴 경우(`last_completed_date < D-1`): 이전 연속이 끊겼으므로 이번 100% 달성 시 `streak_days = 1`로 새 출발하고 `last_completed_date = D`로 기록한다(아직 오늘 100% 달성 전이며 `last_completed_date < D-1`인 조회 시점에는 `0`으로 리셋 가능).
  - 개인 `member_streak_days` 역시 멤버가 `photo` 또는 `rest`를 기록할 때 전날(`D-1`) 활동 여부에 따라 `+1` 또는 `1`로 갱신된다.
- **3일 연속 잠수 멤버 자동 정리 경계 및 방장 승계 규칙** `[설계자 기본값 결정]`:
  - 기준 경계는 오늘(`D`)을 제외한 **직전 완료된 과거 3일(`D-3, D-2, D-1`)**이다. 즉, `joined_at <= D-3`이면서 `last_active_date < D-3`(또는 최근 3일 모두 사진·휴식 기록 없음)인 멤버를 퇴장 대상으로 판정한다.
  - **최후 1인 보호 & 방장(`is_host`) 승계**: 방에 남은 인원이 **1명뿐일 때는 절대 퇴장시키지 않는다**. 퇴장 대상 멤버가 `is_host = 1`인 경우에도 다인 방이라면 퇴장 처리하되, 남아 있는 멤버 중 `joined_at`이 가장 빠른 멤버에게 `is_host = 1`을 자동 승계한다.
  - **데모 모드 보호 및 순수 함수 테스트**: 인터랙티브 데모 모드에서는 현재 체험자(`is_current_user = 1`)의 방 목록이 갑자기 사라지지 않도록 자동 퇴장 대상에서 기본 보호하되, 모든 경계 조건(3일 경계·방장 승계·마지막 1인 보호·본인 포함 케이스)을 검증하는 순수 도메인 함수를 분리해 단위 테스트한다.

### 5.4 로컬 DB 스키마 & REST API
로컬 SQLite(`data/ongi.db`)에 아래 3개 테이블을 둔다.

1. `rooms`: `id`, `title`, `tag`, `category`, `max_capacity` (2|4|6), `streak_days`, `last_completed_date` (`TEXT`, `YYYY-MM-DD`, nullable), `created_at`
2. `room_members`: `id`, `room_id`, `user_id`, `nickname`, `avatar_initial`, `is_current_user` (`INTEGER 0|1`), `is_host` (`INTEGER 0|1`), `member_streak_days` (`INTEGER`), `last_active_date` (`TEXT`, `YYYY-MM-DD`), `joined_at` (`TEXT`, `YYYY-MM-DD`)
3. `daily_checkins`: `id`, `room_id`, `member_id`, `checkin_date` (`YYYY-MM-DD`), `status` (`'photo' | 'rest'`), `image_data`, `note`, `timestamp_label`, `likes_count`, `liked_by_me`, `created_at`

**API 엔드포인트**:
- `GET /api/rooms` — 내 참여 방 목록, 오늘 달성률, 이번 주 흐름(월~일), 탐색용 빈자리 방 목록(검색/필터 지원) 반환.
- `POST /api/rooms` — 새 방 생성 및 개설자(`나`, `is_host = 1`) 자동 합류.
- `GET /api/rooms/[id]` — 단일 방 정보, 멤버 목록, 선택 날짜(기본 오늘) 체크인 및 과거 날짜 목록, 1인 방일 경우 동일 태그 최근 인증 썸네일 반환.
- `POST /api/rooms/[id]/join` — 빈자리 방 합류(정원 초과 시 409 반환).
- `POST /api/rooms/[id]/checkin` — 인앱 촬영 사진(`image_data`)과 한 줄 코멘트(`note`) 저장, 개인·방 연속 일수(`streak_days`, `last_completed_date`) 및 마지막 활동일 갱신.
- `POST /api/rooms/[id]/rest` — 해당 방 이번 주(월~일) 휴식권 잔여 여부 확인 후 휴식 스티커 기록, 개인·방 연속 일수(`streak_days`, `last_completed_date`) 및 마지막 활동일 갱신.
- `POST /api/checkins/[id]/like` — 특정 인증 카드 리액션(`liked_by_me`, `likes_count`) 토글.
- `GET /api/album` — 내 인증 사진 및 휴식 기록을 월/방 필터로 조회.

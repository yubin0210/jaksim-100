# 온기보드 UI·UX 점검

2026년 11월 18일 기준. 로그인·가입, 내 방 목록, 방 탐색·개설, 방 보드·날짜 기록, 카메라, 월간 앨범과 공통 내비게이션을 검토했다. 로컬 로그인 경로의 HTTP 200 및 반환 HTML을 확인했다. 브라우저에서 화면 전체를 시각 검증하지는 못했다. 로그인 이후의 판단 근거는 화면 코드, API, 저장소 구현과 DB 마이그레이션이다. 기존 테스트 4파일 22건과 타입 검사는 통과했다. 실제 계정, 운영 DB의 적용 정책, 모바일 키보드와 실물 카메라 동작은 미검증이다.

## 화면별 사용 흐름

| 화면 | 사용자에게 생기는 문제 | 구체적인 개선 |
|---|---|---|
| 로그인·가입 | 이메일 계정의 비밀번호 복구 진입점이 없다. 로그아웃 상태에서 방 링크로 들어오면 로그인 후 홈으로 이동한다. | 비밀번호 재설정 경로를 추가하고 로그인 성공 시 검증된 앱 내부의 원래 경로로 복귀시킨다. [인증 화면](../src/components/AuthClient.tsx) · [세션 이동](../src/lib/supabase/middleware.ts) |
| 내 방 목록 | 완료한 방만 있어도 첫 제목은 사진을 남기라고 권한다. 신규 회원과 자동 퇴장으로 마지막 방이 없어진 회원에게 같은 빈 화면이 보인다. | 남은 방 수에 따라 ‘오늘 인증할 방 2개’ 또는 ‘오늘 인증을 모두 마쳤어요’를 표시한다. 자동 퇴장 후에는 사유와 보존된 앨범으로 연결한다. [홈](../src/components/HomeClient.tsx) |
| 방 탐색 | 미참여 보드는 구현되어 있지만 탐색 카드에서 제목을 눌러 미리 볼 수 없고 ‘함께하기’는 즉시 가입이다. 3일 미활동 자동 정리 규칙을 가입 전에 알기 어렵다. | 카드 제목을 미리보기로 연결하고 인원·인증 방식·휴식권·자동 정리 조건을 짧게 보여준다. 미리보기의 ‘목록으로’는 탐색 조건을 유지한 채 돌아가야 한다. 현재 목적지는 홈이다. [탐색 카드](../src/components/ExploreClient.tsx) · [보드 헤더](../src/components/RoomBoardClient.tsx) |
| 방 보드 | 다른 멤버가 인증해도 열린 화면은 자체 갱신되지 않는다. 자정을 넘겨 둔 보드도 이전 날짜 상태를 유지한다. 미완료자가 여러 명이어도 ‘내 사진이 올라오면 … 완성돼요’라고 표시한다. | 우선 화면 복귀와 날짜 변경 시 재조회한다. 남은 사람이 한 명일 때만 완성 문구를 쓰고, 평소에는 ‘4명 중 2명이 남겼어요’처럼 실제 상태를 보여준다. [보드](../src/components/RoomBoardClient.tsx) |
| 카메라 | 미리보기는 가변 영역을 채우고 저장 이미지는 600×760 비율로 잘라낸다. 기기 비율에 따라 사용자가 맞춘 구도와 저장본이 달라진다. 셔터는 즉시 게시한다. | 저장할 비율의 촬영 프레임을 표시한다. 촬영 후 같은 프레임으로 결과를 확인하고 ‘다시 찍기’와 ‘보드에 올리기’를 선택할 수 있게 한다. [미리보기](../src/components/LiveCameraModal.tsx) · [저장 영역](../src/lib/camera-adapter.ts) |
| 지난 기록 | 보드 날짜 선택창은 모든 날짜를 버튼으로 늘어놓는다. 시트에 최대 높이와 내부 스크롤이 없어 기록이 많아지면 닫기나 최근 날짜에 접근하기 어려워질 수 있다. | 월 단위로 묶고 내부 스크롤과 고정 헤더를 제공한다. 100일 기록, 낮은 화면에서 첫 날짜와 마지막 날짜를 모두 선택할 수 있는지 확인한다. [날짜 선택창](../src/components/RoomBoardClient.tsx) |
| 내 앨범 | 월을 하나 바꿀 때도 개인의 전체 기록을 조회한 뒤 서버 메모리에서 월·방을 거른다. 장기 사용자의 조회량이 늘고 조회 행 상한에 걸리면 오래된 기록이 월 목록에서도 빠질 수 있다. | DB에서 날짜 범위와 방을 필터링하고 선택 가능한 월·방 목록을 별도로 조회한다. 여러 해 기록이 있는 계정에서 가장 오래된 달까지 검증한다. [앨범 조회](../src/lib/store-supabase.ts) |

## 시각 디자인과 접근성

- **색과 글자.** 크림색 배경, 폴라로이드, 휴식 스티커는 일관된 시각 언어다. 작은 글자의 명도 대비가 아쉽다. CSS 색상값으로 계산하면 흰 글자와 코랄 버튼은 3.22 대 1, 흰 글자와 세이지 버튼은 3.49 대 1, 보조 글자와 아이보리 표면은 2.69 대 1이다. 버튼·필터 문구는 일반 크기 글자 기준 목표인 4.5 대 1 이상으로 조정하고, 연한 색은 넓은 배경에 활용한다. [공통 색상](../src/app/globals.css) · [필터와 버튼](../src/components/ExploreClient.tsx)
- **확대와 읽기.** 로그인 HTML에서도 최대 확대 배율 1을 확인했다. 홈 주간 요일은 기본 글꼴 16px 기준 약 10px다. 확대 제한을 풀고 날짜·상태·내비게이션 레이블부터 키운다. 200% 확대와 가로 화면에서 버튼과 문구가 잘리지 않는지 검증한다. [뷰포트](../src/app/layout.tsx) · [주간 기록](../src/components/HomeClient.tsx)
- **키보드와 화면 낭독기.** 모달에는 대화상자 역할이 있지만 초점 이동·가두기·복원 및 Escape 닫기가 구현되어 있지 않다. 검색 입력의 기본 포커스 윤곽선을 제거했고, 하단 탭의 현재 위치와 필터 선택 상태는 주로 색·굵기로 표현한다. 모달 공통 동작, 보이는 포커스, 현재 페이지와 눌림 상태, 오류 알림을 적용한다. [앨범 상세](../src/components/AlbumClient.tsx) · [검색](../src/components/ExploreClient.tsx) · [하단 탭](../src/components/BottomNav.tsx)
- **화면 폭.** 500px를 넘으면 앱 전체가 최대 430px의 휴대폰 프레임에 들어간다. 데스크톱을 지원한다면 앨범에서는 달력과 선택한 날의 사진을 나란히 보여주고 탐색에서는 더 긴 방 이름을 읽을 수 있게 폭을 사용한다. 모바일 중심 서비스라면 작은 화면, 가상 키보드, 여섯 명 보드의 가독성 검증을 먼저 한다. [전역 레이아웃](../src/app/globals.css)

## 서비스 운영과 검증

- 탐색은 입력할 때마다 전체 방 개요를 조회하고 그 과정에서 비활동 멤버 정리와 참여 방별 휴식권 집계까지 수행한다. 검색 전용 조회를 분리하고 입력을 잠시 기다린 뒤 검색하도록 바꾼다. 검색어를 연속 입력할 때 결과가 안정적인지와 DB 요청 수를 함께 확인한다. [탐색 요청](../src/components/ExploreClient.tsx) · [목록 집계](../src/lib/repository.ts)
- 방 생성과 방장 등록이 별도 쓰기여서 두 번째 작업이 실패하면 방장 없는 방이 남을 수 있다. 사진도 파일 업로드 뒤 기록 저장이 실패하면 파일만 남을 수 있다. 방 생성은 한 트랜잭션으로 묶고 사진은 중복 제출 방지와 실패 파일 정리를 설계한다. [방 생성](../src/lib/store-supabase.ts) · [사진 저장](../src/lib/repository.ts)
- 기존 테스트에 추가할 핵심 시나리오는 프레임 없는 촬영, 촬영 후 오프라인·재시도, 느린 월 전환, 멤버 변경 전후 과거 보드, 키보드만으로 모달 열기·닫기다. 실기기에서는 카메라 권한 거절·재허용, 입력 중 가상 키보드, 노치와 홈 인디케이터가 있는 화면을 확인한다.
